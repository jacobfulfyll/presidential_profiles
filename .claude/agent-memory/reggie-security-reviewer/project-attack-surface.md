`presidential_profiles` is an offline batch pipeline: it reads local parquet files (public-domain presidential speech corpus) and writes static HTML into `docs/` for GitHub Pages. There is no auth layer, no network-facing service, no runtime user input, no database, no secrets in the repo.

**Why:** The corpus is public-domain text; output is static HTML served by GitHub Pages. The only "input" is trusted local data files the pipeline itself generates.

**How to apply:** For security reviews here, most OWASP web categories (injection, authn/authz, session, CORS, CSRF, SSRF) are legitimately N/A — say so with the reason, don't manufacture findings. Effort pays off in exactly two places: (1) dependency hygiene / known CVEs (see [[dependency-cve-calibration]]), and (2) data-integrity guards that prevent silent corruption (keyed merges, `validate=`, post-merge length asserts). Note that HTML output does use `html.escape()` on quoted corpus text — fine, but it's defense-in-depth over trusted data, not an XSS boundary.

**Established provenance model for the profiles HTML renderer (`profiles_site.py`, confirmed again 2026-07-19 in `profile-issue-views`):** the card/profile f-strings interpolate a MIX of escaped and unescaped values, and this split is an accepted trusted-provenance decision — don't re-flag it. Escaped: verbatim speech `quote` (via `html.escape()` in `profiles.py issue_cards()`). Unescaped-but-trusted: issue/taxonomy names, distinctive terms, and `cite` (title/year) — corpus/taxonomy-derived, treated as trusted like the rest of the site. Numeric badges/counts (`share`, `rel`, `n_speeches`, `n_paragraphs`) go through `:.0f`/`:+.0f`/`int()` and cannot carry markup. When auditing a change here, the only thing that would be a real finding is a NEW raw (unescaped, non-numeric) corpus string reaching HTML that isn't in the trusted set above — new numeric formats and new static-constant chips are inert.

**Recurring calibration points (seen across topic/embedding modules):**
- `model2vec.StaticModel.from_pretrained(MODEL_NAME)` where `MODEL_NAME` is a hardcoded public HF id (e.g. `minishlab/potion-base-8M`, defined in `similarity.py`) is the repo's standard offline-embed pattern. It loads from the local HF cache; a cold cache falls back to a one-time HF Hub download of a fixed public model. Treat as INFO, not a network-egress finding — the model id is a module constant, never attacker-controllable, and the pattern predates any given task.
- Corpus/meta artifacts are read back with `pd.read_parquet` (pyarrow, no code-exec) and `json.loads` (safe) — never pickle/yaml. `doc_name` values are public URL slugs like `/the-presidency/presidential-speeches/...`, not local FS paths; committed `data/*.parquet` + `*_meta.json` carry only cluster ids/sizes/term lists/floats. No secrets/PII beyond the public corpus.

**`taxonomy.py` (derive-corpus-taxonomy, reviewed 2026-07-19) is a second paid path, same security posture as `llm_annotations`:** direct synchronous Anthropic calls behind `_client()` (always zero-arg `anthropic.Anthropic()`), `dry_run` returns before `_client()` so it is $0/zero-network. Parsing is `json.loads` only via `_extract_json` (no eval/exec/pickle/yaml; fails closed on refusal/max_tokens/no-text-block). Same re-anchoring trust boundary as ingest: model-returned exemplar sample-ids and coverage-label ids are looked up in a LOCALLY-built `registry`/held-out id list (`registry.get(sid)` drops unknown ids) — a model-invented id like `../../etc/passwd` is just a dropped dict lookup, never reaches a path. `_atomic_write_json` targets are module constants (`TAXONOMY_PATH`/`CROSSWALK_PATH`), not user input; `run_id` (CLI) flows only into the manifest value + `write_manifest`'s filename (the known [[project-attack-surface]] `sanitize-run-id-cli-arg` LOW, in llm_annotations — taxonomy.py adds NO new path-from-input). Tests: conftest `_no_anthropic_creds` autouse deletes `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN`, `anthropic_construction_bomb` fixture proves gates fire before construction; test_taxonomy.py is synthetic-frame, API-free. **The frozen `data/llm_annotations/taxonomy_v1.json` is a TRUSTED input for the next stage (`run-llm-annotation-pass`), scanned clean 2026-07-19:** exemplars stored as `{doc_name,para_idx}` REFERENCES not verbatim text; topic names/definitions/era_notes carry no HTML/JS-significant chars, no prompt-injection phrasing, and no `{}` braces (the only braces in the file are the `{label}`/`{taxonomy}` placeholders in the recorded-provenance `prompts` block — our own templates). So when reviewing run-llm-annotation-pass's embedding of this taxonomy into `.format(taxonomy=...)` prompts, the stored-injection surface is already vetted; re-scan only if the artifact is regenerated.

**`run-llm-annotation-pass` ingest review (2026-07-20, SECURITY PASS):** the two real paid specs (`paragraph_annotations` masked judgment, `speech_annotations` unmasked factual) landed. Spend-control clean: the ONLY `batches.create` is `cmd_submit`, behind the max-cost + `--yes` brakes which `raise SystemExit` BEFORE the zero-arg client is constructed; `count_tokens`/`status.retrieve`/`_fetch_results.results` construct a client but never create a batch (all free/already-paid). chunking/qa/converged-qa/`_all_chunk_escalated_docs` import no anthropic. run_id sanitized in `main()` (rejects `/ \ ..`); `--spec` restricted to `choices`; results re-anchored through `requests_index` (bogus custom_id rejected). Committed artifacts (manifest, `notes/annotation-qa-v1.md`, 3 parquets) scanned clean — aggregate stats + hashed fingerprint + public-corpus strings, 0 secret hits. Two defense-in-depth spots I flagged were CLOSED in round 5 (commit `82d2a27`, suite 327 green): (1) the entity array is now validated inside the guarded per-item loop (`entities` must be a list-of-dicts, empty `[]`/`None` still allowed) so a schema-violating element becomes a `malformed_payload` quarantine instead of an `AttributeError` that aborts the whole paid batch at the downstream `e.get()` explosion; (2) both row assemblies now spread model payload FIRST and trusted keys (`doc_name`/`para_idx`/`run_id`) LAST, so a smuggled key can't clobber the index anchor (the `k != "para_idx"` exclusion is preserved and para_idx is re-set from the validated int). **Reusable heuristic for future ingest edits: the quarantine `except` catches `KeyError/TypeError/ValueError` (NOT `AttributeError`); verify every model-output iteration (esp. nested-array explosions) is inside the guard, and that trusted keys are written LAST so they win.** doc_name never becomes a filesystem path (`annotation_path` takes the trusted spec name only), so even a bypass would be data-integrity, not path/exec.

**Original exception to "no network surface" (added 2026-07-14):** the `pp-annotate` CLI (`src/presidential_profiles/annotate.py` + `llm_annotations.py`) drives the Anthropic Batches API — the pipeline's first paid/networked path. Its security model when reviewing: creds resolved by the SDK from env (`anthropic.Anthropic()` is always zero-arg — no key is ever passed/logged/printed/committed; conftest strips `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` in tests); offline-by-default (dry-run makes zero network calls). Committed provenance artifacts = the review surface: the manifest JSON (`data/llm_annotations/manifests/`) and annotation parquet, which must hold ONLY model/prompt/cost/fingerprint metadata + public corpus text — verified clean. Raw run artifacts (`runs/` — state.json, results.jsonl, requests_index.json) are gitignored. Key trust-boundary design: batch RESULTS are semi-trusted (model output round-tripped through the API), but ingest never lets a result-controlled string reach a filesystem path — it re-anchors `doc_name`/`spec`/`para_idx` through the locally-written `requests_index.json`, rejects any `custom_id` not in the index, and validates every returned `para_idx` against what was sent. Parsing is `json.loads` only (no pickle/eval/yaml), fails closed on malformed input. The one unsanitized path input is `run_id` (a CLI arg → `RUNS_DIR / run_id`), but it's operator-supplied, not a boundary — LOW hardening at most.
