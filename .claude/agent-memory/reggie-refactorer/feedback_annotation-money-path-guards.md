In `src/presidential_profiles/annotate.py` and `llm_annotations.py` (the `pp-annotate` Batches CLI + derived-data layer), much of what looks like over-engineering is a scar from a real defect the review caught. Do NOT collapse, inline, or streamline these — it is a regression even when the 65-test suite stays green (some guards are not exercised by happy-path tests):

- Layered request validation: pydantic `TypeAdapter` over the SDK `Request` TypedDict + unknown-key check + Sonnet-5 `thinking`/sampling guards. The SDK's `MessageCreateParamsNonStreaming` is `total=False` and validates nothing at runtime — the extra layers ARE the guard.
- Atomic results-cache write (`.tmp` + `os.replace`), zero-result refusal, stale-batch (`results_batch_id`) check — each prevents a manifest that lies about cost.
- Coverage-aware `_already_ingested` (subset check, not presence), `sent ⊆ returned` / `returned ⊆ sent` guards, dup-custom_id / dup-para_idx raises.
- Submit money-gates (`--yes`, `--max-cost-usd`, `BATCH_MAX_*`) firing before client construction.
- The migration's exact 69/32 assertion and the ±110-vs-±130 provenance note in `migrate_invocation_tone`.

**Why:** This is the one command in the pipeline that spends money; a bad payload means a wasted paid batch or a false provenance record. Several tests assert on `notes`/error substrings, so string edits break tests — grep before touching any message.

**How to apply:** When a SIMPLIFY pass lands on these two modules, the only clearly-safe cleanup is genuine redundancy (e.g. the logged `submit-double-loads-corpus`: `cmd_submit` reloaded the corpus for the fingerprint after `_prepare` already had it — fixed by threading the frame through, verified byte-identical). Note that the submit fingerprint must cover the FULL corpus even under `--limit`, so compute it before `_prepare` caps the frames. Otherwise report the code as already tight rather than inventing churn.

Calibration from the `run-llm-annotation-pass` SIMPLIFY pass (annotate.py +506 lines: pilot sampler, entity explosion, QA report, cross-batch manifest accumulation, sealing): the new code arrived already tight (three review stages at 9.4-9.5), so the pass was mostly comment/docstring accuracy fixes, not restructuring. Two recurring judgment calls:
- **Placeholder-in-default-`--spec`-set**: a bare `submit` (no `--spec`) defaults to ALL of `FIELD_SPECS` incl. the dev-only `placeholder`. The right SIMPLIFY answer is LEAVE IT — excluding it would ADD a "default subset" concept (a new FieldSpec flag or a name-based special-case in `_specs`), which is out of SIMPLIFY's charter (remove complexity, don't add config). The footgun already self-defends: 3-spec estimate ≈$29 > the $25 `MAX_COST_USD` ceiling aborts before spend, and the documented paid procedure passes explicit `--spec`.
- **Per-test synthetic corpora are NOT DRY targets**: masking/qa/entities test files each build their own tiny corpus tuned for that file's assertion legibility (distinctive `_PRESIDENT` string, controlled flag counts, nested entity arrays). Consolidating them hurts readability. conftest already shares the real infra (`forge_run`/`succeeded_line`, `Args`).
- Money-path pilot narrowing (`paragraphs[...isin(pilot doc_names)]`) is duplicated in `cmd_dry_run` (offline) and `cmd_submit` (paid); left un-extracted because `cmd_submit --pilot` is NOT directly tested (WRITE-TESTS declared it), so a helper extraction there would edit untested money-path for a 2-line win — not worth it.

Calibration from the `inter-model-agreement-check` SIMPLIFY pass (NEW `agreement.py` ~575 lines + an `annotate.py` MOD adding `--model`/`--sample`, per-model pricing/tables): the new code arrived tight (IMPLEMENT 9.42; WRITE-TESTS pins default-model request params BYTE-IDENTICAL in `test_agreement_model_plumbing.py` — treat as a contract). Net diff was ~11 lines across two edits: (1) the orchestrator-sanctioned error-path hardening in `agreement._load_joined`'s speech branch — it keys on the OPUS speech table existing but then unconditionally reads the PRIMARY, so a missing primary raised an opaque Arrow error; added a clear `FileNotFoundError` (happy path untouched, no test change); (2) a single genuine dedup — the intro-window predicate `intro_ends is not None and today <= intro_ends` was duplicated between `ModelSpec.rates()` and the module-level `_intro_applies`, so I added `ModelSpec.intro_applies()` and delegated both (both directly test-covered). LEFT ALONE (noted, not fixed): `agreement.sample_doc_names` and `annotate._load_sample_docs` both extract `doc_names` (falling back to `speeches[].doc_name`) from the sample JSON, but consolidating means either a lazy import (agreement→annotate already exists one-way, so annotate→agreement would cycle) or a new shared module, AND their error semantics differ (exceptions vs CLI `SystemExit` + corpus-membership validation) — extraction ADDS structure for a ~3-line win with divergent behavior, not a net simplification. This module family keeps producing near-empty-diff SIMPLIFY passes: pure helpers + thin IO wrappers, guards are load-bearing.

`taxonomy.py` (the `pp` corpus-taxonomy pipeline, `derive-corpus-taxonomy` task) is a THIRD module in this family: same design (every paid call behind a `_client()`-taking fn; `run()`/`main()` spend real money and are untestable API-free). Calibration from a SIMPLIFY pass there: `run()` can't be exercised by the suite, so keep changes to it MECHANICAL/minimal — do the real simplifying in PURE extracted helpers that ARE unit-testable (this pass added `_is_covered`/`uncovered_ids` sharing one predicate so the coverage gate and revise_merge input can't drift, and `_atomic_write_json` for tmp+rename artifact writes). Don't extract a helper that wraps a paid call just to dedup two call-sites in `run()` — the dedup isn't test-verifiable and muddies the "paid calls isolated behind named fns" design. Expect the net line delta to go POSITIVE on a taxonomy pass: the judge-sanctioned fixes are additive (new report fields, testable helpers, atomicity) and outweigh the removals.
